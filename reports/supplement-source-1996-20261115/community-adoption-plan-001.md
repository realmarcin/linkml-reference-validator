1. In a fresh CommunityMech branch/environment, adopt the independently reviewed
   shared schema through the native Claw governance/manifest/lock workflow.
   Keep `reference` and excerpt annotations intact and add only the optional
   inlined locator. Structural null permissiveness is distinct from runtime
   rejection of a present null. Preserve frozen record-lane checkouts.
2. Pin the reviewed owned runtime commit or exact built artifact, and update
   the lock deliberately. Resolve its Git-derived version explicitly; do not
   assume the unchanged version string proves the installed candidate. Compare
   every installed package Python member and bytes with the reviewed artifact,
   and record dependency versions in the fresh environment.
3. Prepare a separate retained source namespace from the already acquired
   pinned DOCX. Generate the v2 projection mechanically and the reviewed catalog
   with exact parent/asset/version/path/digest bindings. Configure its explicit
   path without altering article caches. Missing retained assets or catalog
   must remain hard failures; a fresh checkout does not gain a fallback.
4. Before any canonical edit, repeat the one-record scratch canary through the
   actual CommunityMech native launcher and its resolved environment. Measure
   all 37 comparisons and the three exact identities; retain the article-only,
   wrong-cell, wrong-parent and restoration controls. Preserve ordinary matching,
   literal brackets, unknown-prefix behavior and annotation coverage controls.
5. Only after that persistence and independent review, a separate bounded
   record change can add the three reviewed locators. Preserve all snippets,
   parent PMIDs, scientific ambiguities, historical source claims and the
   open scientific findings. Run the native schema/reference/history checks,
   scoped review and complete input checkpoint before downstream completion
